                          Model explanation

                          How the automation assessment works

                          The tool separates automation fit from business value so it does not blindly recommend automation. A process can be easy to automate but still not worth doing, or valuable but too risky without preparation.

                          Automation fit

                          Measures whether the process is rule-based, stable, repeatable, low judgement, and technically practical.

                          Business value

                          Measures whether the process has enough time cost, urgency, volume, and business impact to justify work.

                          Decision advisor

                          Chooses between automate now, improve first, integrate systems first, use decision support, or do not automate yet.

                          Confidence

                          Explains how reliable the estimate is based on process clarity, system complexity, judgement, and volume.

                          Fully burdened labour

                          Manual cost uses hourly cost plus overhead, so benefits, equipment, payroll costs, and hidden operating load are reflected.

                          Total cost of ownership

                          Net savings subtract estimated monthly automation TCO, such as licensing, maintenance, support, and platform costs.

                          Error and rework savings

                          The calculator estimates avoided error cost from process volume, error frequency, rework cost, and automation coverage.

                          Scaling and opportunity value

                          It models one-year volume growth and adds a value estimate for reallocating saved human time to higher-value work.

                          Data import

                          Excel-exported CSV files can improve the estimate by calculating volume, handling time, error rate, and rework cost from real process records.

                          Risk range

                          The report shows conservative, expected, and optimistic outcomes so reviewers can see uncertainty instead of trusting one fixed number.

                          Inputs
                          Fit and value scoring
                          Decision advisor
                          Roadmap and report

                          Australian assumptions and formulas

                          1. Currency is fixed to AUD and the model uses Australian city cost indexes for labour estimates.
                          2. Burdened hourly cost = base hourly cost x city cost index x (1 + labour overhead %).
                          3. Current monthly manual cost = hours per week x burdened hourly cost x 4.33 weeks.
                          4. Labour saving = monthly manual cost x automation coverage, where coverage is based on readiness.
                          5. Error saving = weekly volume x 4.33 x estimated error rate x rework cost x automation coverage.
                          6. Net monthly saving = labour saving + error saving + opportunity value - monthly automation TCO.
                          7. Payback = estimated build-cost band divided by net monthly saving, only when the saving is meaningful.

                          Validation and review standard

                          The formulas are built from common ROI, TCO, workflow automation, and process discovery concepts, but the numbers should be calibrated with real company data before a business relies on them for investment approval.

                          1. Validate time estimates with a process owner or time study.
                          2. Validate labour and overhead assumptions with finance or payroll.
                          3. Validate TCO with IT, software owners, or the automation vendor.
                          4. Validate error and rework assumptions with actual exception logs or sample records.
                          5. Use the report as a discovery screen, then complete stakeholder review before spending money.

                          Portfolio write-up

                          Case study: automation discovery for manual business workflows

                          This project simulates the first stage of an automation consulting engagement: understanding a manual process, estimating value, identifying risks, and recommending the safest next move.

                          Executive summary

                          I built a browser-based automation discovery tool that helps a business decide whether a manual workflow should be automated now, improved first, supported with AI, integrated across systems, or left alone for the moment. The goal is to make automation decisions more realistic by combining ROI, process readiness, risk, and strategic value.

                          1. The app collects process, labour, error, tool, judgement, and growth assumptions.
                          2. It calculates automation fit, business value, confidence, net monthly saving, payback, and scaling impact.
                          3. It produces a decision, reason codes, readiness checklist, roadmap, workflow comparison, and printable report.

                          Problem

                          Businesses often automate too early or choose the wrong tool before understanding process readiness, true labour cost, system complexity, and risk.

                          Approach

                          I built a transparent rules-based model that compares readiness, savings, TCO, complexity, confidence, risk, payback, and long-term scaling benefit.

                          Result

                          The app produces an explainable recommendation, roadmap, checklist, workflow comparison, and printable report.

                          Target users

                          The tool is designed for small business owners, operations teams, consultants, and automation analysts who need to quickly screen a manual process before investing in RPA, workflow automation, AI support, or system integration.

                          Why this matters

                          A weak automation business case can waste time and money. A strong assessment should show not only how much time is saved, but also whether the process is clear enough, stable enough, and valuable enough to automate.

                          Key design decision

                          I separated automation fit from business value. This is important because a process can be technically easy to automate but not worth the investment, or financially valuable but too risky until the workflow is improved.

                          Scoring model

                          The model uses process type, hours, burdened labour cost, volume, error frequency, tool complexity, human judgement, process clarity, TCO, opportunity value, and annual growth to produce a recommendation.

                          Example assessment

                          Invoice processing workflow

                          A finance team spends 12 hours per week manually processing around 80 invoices. The base hourly cost is $35, with 30% overhead, medium error frequency, and a monthly automation TCO estimate of $350.

                          DecisionAutomate now
                          First featureDuplicate detection + approval routing
                          PaybackAbout 1 month
                          WhyHigh volume, low judgement, clear workflow

                          What makes it different

                          The app does not always say yes to automation. Low-readiness cases are told to document the process, standardise inputs, clean data, and reassess later. High-judgement cases are directed toward AI decision support instead of full automation.

                          Business deliverable

                          The output acts like a lightweight consulting report: recommendation, reason codes, ROI estimate, risk severity, readiness checklist, required inputs, manual-versus-automated workflow, and a practical roadmap.

                          Technical implementation

                          The project is built as a static HTML, CSS, and JavaScript app. All calculations run locally in the browser, so it needs no backend, login, paid API, database, or customer data storage.

                          Limitations

                          The calculator is a discovery tool, not a guaranteed financial model. Real projects still need stakeholder interviews, process observation, system access checks, security review, and validation against actual business data.

                          Australian business context

                          I narrowed the model to Australia so the calculator feels more realistic and less generic. The report uses AUD, major Australian cities, and city-based cost indexes to adjust labour assumptions before overhead is applied. This makes the output easier for an Australian business, consultant, or operations team to review.

                          1. Region is fixed to Australia and currency is fixed to AUD.
                          2. Users choose a major Australian city such as Sydney, Melbourne, Brisbane, Perth, Adelaide, or Canberra.
                          3. The city cost index slightly adjusts base hourly labour cost before overhead is added.
                          4. The report clearly lists the assumptions so finance, operations, and IT can challenge or approve them.
                          5. The tool is positioned as an automation discovery report, not a black-box ROI promise.

                          What this project demonstrates

                          1. Ability to translate a business consulting problem into a working product.
                          2. Understanding of ROI, TCO, opportunity cost, process readiness, and risk.
                          3. Practical frontend implementation with dashboard-style reporting and print output.
                          4. Product thinking: the app recommends the safest next move, not just the most exciting technology.
